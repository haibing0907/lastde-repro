### 2.2 `auroc()`（第 33–58 行）

作用：算 AUROC，不依赖 sklearn。

原理是**秩和公式**（Mann-Whitney U）：

```
AUROC = (正样本的秩和 − n_pos(n_pos+1)/2) / (n_pos × n_neg)
```

- 把所有分数排序，AI 的分数如果普遍靠前，秩和就大，AUROC 就高。
- 第 48–53 行处理**并列分数**：并列的取平均秩，避免随机性。
- 第 39 行：如果只有一类样本，返回 NaN，防止除零。

**为什么不用准确率？** 准确率要先定阈值，阈值一换结果就变；AUROC 遍历所有阈值，衡量的是排序能力，更公平。

### 2.3 `load_model()`（第 63–79 行）

### 2.4 `token_logprobs()`（第 82–93 行）—— **核心 1：TPS**

```python
ids = tok(text, return_tensors="pt", truncation=True, max_length=max_tokens).input_ids
logits = model(ids).logits
logp = torch.log_softmax(logits[:, :-1, :], dim=-1)
picked = logp.gather(2, ids[:, 1:].unsqueeze(-1)).squeeze(-1).squeeze(0)
```

逐行解释：

| 行 | 在干什么 | 形状 |
|---|---|---|
| 85 | 文本 → token id，超长截断到 `max_tokens` | `(1, L)` |
| 90 | 喂给 GPT-2，得到每个位置的词表打分 | `(1, L, 50257)` |
| 91 | 只取前 L-1 个位置，做 log_softmax | `(1, L-1, 50257)` |
| 92 | 取出“真实下一个词”的那一项 | `(L-1,)` |

**为什么是 `logits[:, :-1]` 配 `ids[:, 1:]`？**
第 i 个位置的输出，预测的是第 i+1 个词。所以第 1 个位置的概率没有“前文”，用不了，整条序列天然少一个。

**这就是论文式(1) 的 TPS**：`(log p(t₁), …, log p(tₙ))`。

### 2.5 `_cosine_adjacent()`（第 98–112 行）

```python
w = sliding_window_view(x, s)   # 所有长度为 s 的窗口
a, b = w[:-1], w[1:]            # 相邻两个
out = (a*b).sum(axis=1) / (|a|*|b|)
```

- 对应论文 3.1 节的“滑窗切分 + 余弦相似度”。
- `sliding_window_view` 是 numpy 的零拷贝滑窗，比手写循环快。
- 第 110 行 `denom > 1e-12`：防止除零（全零窗口）。

### 2.6 `_de()`（第 115–125 行）—— **核心 2：多样性熵**

```python
sims = _cosine_adjacent(x, s)
hist, _ = np.histogram(sims, bins=bins, range=(-1.0, 1.0))
p = hist[hist > 0] / hist.sum()
DE = -(p * np.log(p)).sum() / np.log(bins)
```

三件事：

1. 把相似度按 [-1,1] 分 `bins` 个格子，数直方图；
2. 归一化成概率分布 `p`；
3. 算香农熵，再除以 `log(bins)` 归一化到 [0,1]。

**这就是论文式(6)(8)**：概率状态序列 → 多样性熵。

`hist[hist > 0]` 是为了跳过 0 概率的格子（`0·log0` 会变成 NaN）。

### 2.7 `aggmde()`（第 128–142 行）—— **核心 3：多尺度**

```python
bins = max(10, int(eps_mult * n))          # ε = 10n
for tau in range(1, tau_max + 1):
    pooled = np.convolve(x, np.ones(tau)/tau, "valid")   # τ 尺度平均
    vals.append(_de(pooled, s, bins))
return np.std(vals, ddof=1)
```

| 论文 | 代码 |
|---|---|
| 多尺度变换：相邻 τ 个取平均 | `np.convolve(..., ones(tau)/tau, "valid")` |
| ε = 10×n | `bins = 10 * n` |
| 每个尺度算 DE | `_de(pooled, s, bins)` |
| MDE 序列聚合（Std） | `np.std(vals, ddof=1)` |

**为什么 `ddof=1`？** 官方 `fastMDE.py` 用的是 `torch.std`，默认无偏（除以 n−1）。我们一开始用 `np.std`（除以 n），和官方差了约 11%，改成 `ddof=1` 后误差降到 **1e-8**：

```
我们:  0.010395885
官方:  0.010395901
```

这一点答辩时值得讲：**细节对齐才叫复现**。

## 4. 五个“为什么这么写”

1. **为什么用平均对数似然而不是求和？**
   求和会随文本变长越来越负，长度就成了作弊信号。取平均是长度归一化，和官方 `log_likelihood.mean(dim=1)` 一致。

2. **为什么 ε 要随 n 变？**
   文本越长，相似度取值越多，格子也要越密，否则全挤在一格里，熵恒为 0。这就是论文的 ε = 10n。

3. **为什么 τ 从 1 到 5？**
   τ=1 是原始序列，τ 越大越平滑。论文敏感性分析（Fig.3）发现 5~10 最好，默认 5。

4. **为什么要跳过短文本？**
   少于 30 个 token 时，滑窗片段太少，直方图几乎是空的，DE 没有意义。

5. **为什么最后取标准差？**
   5 个尺度的 DE 组成 MDE 序列，标准差衡量“不同尺度下波动差异有多大”。论文附录 D 也比较了 2-Norm、Range、ExpStd。

## 8. 常见问题

**Q：为什么不用 sklearn 的 roc_auc_score？**
A：可以，但那样就多一个依赖；而且自己实现能讲清楚“秩和”原理。

**Q：为什么用 CPU 不慢吗？**
A：GPT-2 只有 1.24 亿参数，300 条短文本 1~3 分钟；上 GPU 要重装 torch，不划算。

**Q：`sliding_window_view` 和官方的 `unfold` 一样吗？**
A：数学上等价，都是“长度为 s、步长 1 的窗口”。官方多一个 batch 维度，我们用一维。

**Q：如果 AUROC 低于 0.5 怎么办？**
A：说明分数方向和标签反了，报告写 `1 − AUROC`，并检查 csv 的 label 列。
